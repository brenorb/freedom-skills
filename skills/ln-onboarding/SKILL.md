# Lightning Onboarding

Recommend a fit, not a single universal wallet.

## Workflow

1. Ask only the questions that change the choice: receive/send, amounts,
   frequency, custody tolerance, backup ability, privacy, offline needs,
   merchant/node use, and jurisdiction.
2. Compare two or three current options across custody, recovery, fees,
   liquidity, privacy, Lightning/on-chain behavior, open source, and failure
   modes.
3. Start with a small test payment and explain invoice, address, fee, expiry,
   and support boundaries in plain language.
4. Verify backup/recovery before increasing balance; distinguish custodial,
   federated, and self-custodial models.
5. Give migration/export and incident steps so the user is not trapped by the
   first choice.

Never promise instant, free, private, or irreversible payments without naming
the actual tradeoff.

## Minimal check

The recommendation states custody, recovery, and loss scenario for the chosen
option.
