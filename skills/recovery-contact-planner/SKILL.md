# Recovery Contact Planner

Turn “someone can help me” into a tested, bounded recovery procedure.

## Workflow

1. List the events that trigger help: lost device, account lockout, illness,
   detention, travel, or inability to communicate.
2. Assign separate roles for welfare check, technical recovery, legal/family
   contact, and secret custody; avoid giving one person everything by default.
3. Define verification phrases or independent channels, what information each
   role may receive, expiry/revocation, and the safe escalation path.
4. Store only the minimum contact data, protect it from ordinary sync, and
   rehearse the procedure without using real secrets.
5. Review after role, device, relationship, or threat-model changes.

Do not create a covert access path or share credentials as a substitute for a
recovery plan.

## Minimal check

Each trigger has a verified contact, an authorization test, a bounded action,
and a revocation method.
