# Takedown Resilience Planner

Create a continuity plan that reduces single points of failure without turning
the plan into covert operational instructions.

## Workflow

1. Inventory the publication, domain, accounts, source files, credentials,
   contacts, legal obligations, and recovery owners.
2. Identify failure modes: host removal, domain seizure, account lockout,
   payment loss, DDoS, moderation action, operator absence, or device loss.
3. Select independent, authorized alternatives: static mirror, archived copy,
   onion publication, IPFS CID, alternate domain, and offline release bundle.
4. Assign owners, access boundaries, update cadence, verification steps, and a
   communication tree. Keep private recovery material out of public copies.
5. Run a tabletop failure exercise and document what worked, what leaked, and
   how to roll back stale mirrors.

Do not evade a lawful access control or publish another person's private data.
Call out jurisdictional, safety, and consent constraints.

## Minimal check

The plan must have two independently controlled recovery paths and a tested
restore procedure.
