# Tool Migration Guide

Move the workflow, not just the application, and keep the old path available
until the new one is proven.

## Workflow

1. Inventory current data, identifiers, contacts, keys, integrations, history,
   permissions, backups, and failure dependencies.
2. Compare source and destination on custody, privacy, metadata, export/import,
   compatibility, availability, and account recovery.
3. Build a staged plan: backup, test account/data, small pilot, dual operation,
   verification, user notice, then retirement.
4. Migrate only approved data, scrub unnecessary history/metadata, and verify
   recipient/profile/wallet mappings before external sends or funds movement.
5. Revoke old access only after the new recovery drill passes; record rollback,
   offboarding, and retention decisions.

Do not claim portability where the source cannot export a critical dependency.

## Minimal check

The pilot proves data integrity, user recovery, permission scope, and rollback
before the old tool is retired.
